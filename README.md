# 叫号条（Callslip）

银行网点柜面叫号：取号入队 → 叫号推进 → 过号回收/重叫 → 当日队列封口。

- 前端 http://127.0.0.1:6400
- API http://127.0.0.1:11400
- `docker compose up -d --build`

## 双写口（办结 / 过号）并发争用仲裁

全局唯一口径 **「办结写口优先」（WRITE_POLICY）**，禁止与「过号打断」口径混用：

- 办结意图先生效 → 号牌终态 `已办结`、窗口指针释放、写「办结」事件；随后过号写口**整笔硬拒 409**，不写过号事件、号牌不进过号回收。
- 过号先生效 → 号牌落 `过号`、窗口随过号释放；此后办结写口**硬拒 409**（已过号不得再改已办结）。
- 两个写口在 `BEGIN IMMEDIATE` 串行事务 + 状态条件更新（CAS）下闭合，号牌任一时刻只有一个终态，杜绝一结一过双终态；CAS 失败或任何异常整笔回滚到争用前快照。
- 每笔意图（含被拒）记入 `ticket_intents` 台账，含争用前状态/窗口快照、拒因、胜方意图；同一 `请求键` 重放返回原结局且零新增写入。
- 回执、号牌终态、窗口空闲、叫号事件、办结页、过号回收列表、总览两桶在同一事务提交，天然同刷。
- 假办结收口口径：办结灯必须能由「号牌唯一终态 ∪ 窗指针收口 ∪ 总览已办结桶」同命运重放；出现办结∪过号双终态即整笔回滚。总览两桶仅由 `tickets` 实表聚合，回执即事务内终态——不存在任何事务外覆盖/粉饰层；历史上遗留的 `surface_*` 假账键在启动建库时一律清除。
- 仅覆盖办理中号牌的双写口争用；过号回收命运与重叫位次另有链路。

测试：`PYTHONPATH=backend python -m unittest discover -s backend/tests`
